Taxi Request Rules

Rules a taxi request is checked against. The result is a live formula in the checks tab: the Slack workflow reads it and posts it in the request's thread. No Slack app, no trigger.

Requests

The column the workflow fills with Time when workflow started (e.g. "Date ID"). It is copied to the checks tab so the workflow finds exactly this request.

Slack workflow steps
  1. Add a row to a spreadsheet (as now) → the requests tab.
  2. Add Google Sheets → Select a spreadsheet row: this spreadsheet, tab Taxi Checks, column Date ID (your request ID column) = Time when workflow started, the same variable step 1 wrote. Without an ID column: Name = the requester (the newest request is the first row).
  3. Send a message to the channel (as now, information only).
  4. Add Send a message as a reply in the thread of step 3's message, with the selected row's Message and the Prebooked / Deny buttons (a message with buttons waits for the click, so they belong here). To record the decision, Update a spreadsheet row in the requests tab where Date ID = Time when workflow started. Optional: if your workflow can branch, post only when Result is CHECK.

Change the rules here at any time: Save rewrites the formula, and the workflow keeps working. Save again after adding a team or moving staff columns.
